# 通用 AI 视频剪辑

## 按当前要交的成果选做法

开工先看交付物、受众与发布场景，再看本期已有的稿、原声、素材、工程、已确认版本及最近反馈。结合上文和栏目惯例理解简短委托。由剪辑师选择并实际使用当前需要的方法和工具，用户只需说明想拿到什么。一个任务可以同时用几种方法；每交接到下一阶段，按新状态继续，沿用已经确认的决定。

例如，创作者在既有抖音栏目里说“做一期给新手看的工具教程”，只有选题时，从作者发布片和优质同类片取样、起稿，钩子后直接带观众做第一步，再按本期交付范围接分镜和备料。若同时给了锁定配音，从这条声音定位第一步、配真实操作画面。若此轮只讨论稿子，交一版可朗读的稿，在约定阶段收住。

| 当前的目标或素材状态 | 该用的方法与交付 |
| --- | --- |
| 短视频口播还缺稿，或已有草稿的开头、表达需要修改 | 用[抖音口播起稿与审稿](references/douyin-spoken-scripts.md)处理抖音及采用同类表达的栏目。用作者发布片校准说法，用优质同类片找进入实操的时机。保留指定开头、亲历、数字和条件；影响意思的疑点单列。 |
| 观众需要在两种做法中选择，或本期要回答真实售前顾虑 | 在起稿和安排证据画面时用[决策型视频写法](references/decision-led-video.md)。找出改变结论的条件，给观众能自己核对的依据。已有定稿声音就按原声选镜。 |
| 镜头节奏、构图或叙事手法需要参考 | 从已有同类发布片和参考记录找最接近的片段，区分实测时码、看见的变化和编辑判断。遇到要比较不同剪法的取舍，查[剪辑工作流的对照与同片验证](references/editorial-benchmark.md)。属于已有垂直栏目时同时采用栏目约定，阿桂校园片搭配 agui-horizontal-video。 |
| 原始口播有重录、停顿，或长访谈要剪成能单独听懂的短片 | 用[口播粗剪与逐词校对](references/general-templates.md#原口播先做一遍候选粗剪)标出候选范围并试听。访谈选段记录源入出点、首句、结尾和必要上下文，核对人称指代、问答与前后意思后给每条配镜。 |
| 稿子或配音已就绪，需要把内容变成镜头 | 用[逐句方案与备料单](references/packaging-plan.md)把每句话对到可见的对象、动作或结果。按[通用镜头模板](references/general-templates.md)选合适的表现方式。采访初次出场要认人，操作要看真界面，对比要认清同一对象的变化。案例演示到足以说明本步就回主线。 |
| 要交带声视频，已定稿但缺旁白 | 核对本期已有的人声、栏目约定和可用配音方式。在已授权范围内录制或生成旁白，试听专名和语速，再按实际音轨校正分镜、字幕和动作落点。 |
| 分镜已确认，进入制作或收到局部返修 | 找到对应工程、可用素材及已有授权，核实后继续剪。反馈“太空、看不清、拖”时，回到相应原话、画面和声音定位原因，再检查同片同类镜头。字幕错时、受保护区域比较、交片规格或长停顿需要工具时，选[工作台剪辑工具](references/workbench-video-tools.md)中相应一项。 |
| 画面切换、圈注、字幕、口播速度或声音需要设计 | 按[动效与声音](references/motion-and-sound.md)让停顿、标注、重点词和音效落到实际动作。已有约定速度就沿用，其余按听觉和手机阅读负担定速。整片风格调整先交[连续带声样片](references/review-and-learning.md#改风格先看连续样片)，沿用已确认的同范围样片继续制作。 |
| 只改声音或需要比较配乐 | 锁住已确认的画面、人声起点和应保留的声音。补拟音跟动作，换音乐从分轨或已有无配乐底版重混。需要比较的版本沿用同一人声电平；只有混合轨时先查工程，说明能恢复的范围。 |
| 已导出审片、交整片或收到发布版 | 依[成片检查](references/review-and-learning.md#成片文件怎么验)核对实际文件、反馈时码和片尾。交整片候选时点名询问是否定稿，已有明确答复就按项目授权范围[归档并处理可清理文件](references/review-and-learning.md#整片定稿后归档与清理)处理。样片或文案通过只推进对应阶段。 |

能根据原件和已有约定判断的剪辑选择直接做。已定文案、锁定的原声、只要样片等界限随任务沿用。具体素材下载、付费、上传私人素材及定稿清理按下文和各阶段已有授权执行；缺哪项只问哪项。

## 从接稿到开剪

整片委托按实际进度接续以下环节。单项交付只做与目标有关的部分。已有同版方案、同批素材或开剪确认时，直接引用相应记录。

1. **先读素材。** 读项目归档规则和相近项目的复盘。盘点给定文件及已有素材库，检查真实内容、画幅、音轨、时长、可读性和使用范围。先找再索要。如果已有成品配音，提取实际声音，辨别已混入的音乐、音效、停顿；标明哪一轨作时间基准。用户让保留原声时，原混音贯穿剪辑。
2. **为要剪的新片写逐句方案。** 用[方案与备料单](references/packaging-plan.md)交付逐句对照。每句写成片起止、原话、要让观众看到的具体对象或变化、对应素材及源时码、构图与动作、如何切出、字幕重点、音乐与音效落点。连续演示可覆盖多句。没有成音用估时，拿到成音后按实际话语重排。已录口播与稿子不同，以原声对字幕；涉及事实错误时单列给作者决定。每处缺口给出具体替代或最少补拍要求。
3. **按方案搜罗。** 分成网上取得的素材、AI/设计制作的素材、必须由用户提供的真实素材。已有本地合适素材先复用，保留原来所属类别与出处。可在确认前检索和查看作品页，在站内预览、记链接。**每次从网站下载任何视频、图片、BGM、SFX、图标或代理文件之前，先列具体条目，让用户明确批准这批或其中某几项。** “开始剪”、通过文案、同意某个平台、只有搜索关键词，都不能代替下载确认。计划与逐项下载可一次确认。已批准的同一条目可安全重试；新增、换片、换作品、收费或用途权利改变时，就变化项重新确认。按用户确认的生成方案执行生图；使用付费服务、上传私人参考或额外支出前按实际授权处理。
4. **素材到齐再开剪。** 实看选中区段，校验来源、可用时段、动作方向、裁切与隐私。审阅表写出“就绪／需要替换／需本人提供”。有缺口先回给用户选择具体替代；原画面已够用可跨句沿用。已确认方案和开剪授权可合并，列内素材就绪后直接执行，不重复问同一件事。
5. **按声音定剪点。** 用[动效与声音手册](references/motion-and-sound.md)选择有作用的动作，按实际发生时刻落键帧、音效和字幕；示意图和动态数据必须区分。尊重既有工程入口。工具可选现有剪辑工程、FFmpeg、Remotion 或其他本机已验证后端。审片先输出新版本并保留可回改时间轴、字幕、来源及需署名信息。
6. **审片、留经验。** 检查实际导出的片子，给用户可播放版本和关键时码。收到反馈、交付或发布版回流时，用[复盘与垂直派生](references/review-and-learning.md)把这一期的结果写入所属项目，下次开剪先读。只给文案或方案的回合可在项目方案内记决定，不能编造成片或观众效果。

每当生成、下载或接收一份后续会用的素材，按[素材入库与检索](references/packaging-plan.md#素材到手就按用途入库)放到稳定位置并登记，再让剪辑工程引用它。交整片时落实上表的定稿确认。

用[可复制的计划样例](assets/plan-example.json)记录机器可读时间轴。已有 Excel、Markdown 或剪辑工程可保留人用格式，按同一字段复核；需要自动检查时运行 `python scripts/check_plan.py 项目计划.json`。脚本只读取计划，能校核覆盖、时序、待下载范围和开剪条件，不能替人确认、下载或渲染。

GitHub 方法的冻结版本、许可证与可查原文见 [上游资料](upstream/sources.md)。它们提供实现参考，联网、下载和发布权限以当前项目授权为准。

审片时先回看被点名的镜头，再核最终导出的文件。用 [成片检查方法](references/review-and-learning.md#成片文件怎么验) 复核解码、声轨、字幕时序；只改声音时还可比对底版视频流和每包的时间戳。选材贴不贴原句、动作能否看懂、音乐会不会抢字，分别靠看和听判断。交片时写出本次实际查过的时码和结果。
