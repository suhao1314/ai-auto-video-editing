# 通用镜头模板与口播粗剪

拿到新稿，从“这句话需要观众认出谁、看懂什么变化、看见哪个操作结果”选镜头。只在需要的句子调用模板。没有个人栏目要求时，从当期产品或客户已有的字体、颜色、素材和画幅出发。

可用[本地 MP4 模板](../assets/generic-explainer-template.md)生成自己的演示片；演示素材不随技能分发。

| 片种和口播时刻 | 直接拿什么用 | 需要先有的材料 | 交片前看哪里 |
| --- | --- | --- | --- |
| 访谈、人物故事。受访者第一次说话 | HyperFrames 的 [lt-clean-bar 姓名条](../upstream/heygen-hyperframes/registry/lt-clean-bar/lt-clean-bar.html) | 授权采访、核对过的姓名和身份。人物继续占主画面，条放在脸和字幕以外的留白 | 名字读完再退场。同一段采访中只在需要重新辨认人物时再次出现 |
| 工具测评、设计改版、实物前后变化 | [before-after-wipe 对比划屏](../upstream/heygen-hyperframes/registry/before-after-wipe/README.md) | 同一个对象的两个真实状态，先对齐视角、大小与关注点。用“原图／裁剪后”等具体标签 | 观看者能在同一位置指出变化。变化项很小就裁到同一局部，除非有依据，不用动画暗示因果 |
| 软件教程、服务操作。由一个界面切到另一个结果 | [browser-device-stage 演示窗口](../upstream/heygen-hyperframes/registry/browser-device-stage/README.md) | 真实操作前后截图，或已经获得的完整录屏。双图演示状态变化，观众需要模仿手势时换原录屏 | 保留版本、按钮和反馈，切屏不能跳过决定结果的步骤。不同录屏用各自的时间轴 |
| 一句旁白带一个要看清的操作，或需要可直接剪入的横屏片段 | [本地 MP4 模板](../assets/generic-explainer-template.md) | 可换当期录屏、截图、实拍或标题。无真实材料只能用标为示意的样片试版 | 对照输入素材源时码，核对结果停留、字幕安全区和短素材的结尾 |

### 用三份 GitHub 原组件快速试镜头

从通用技能目录运行。先准备已获准使用的本地素材，输出路径选项目中一个新文件。以下命令直接生成可双击播放的 HTML，适合包装方案预览。预览引用本地图片和 GSAP，分发给别人时可使用导出的 MP4。

```powershell
python -X utf8 -B scripts/preview_component.py --gsap "./gsap.min.js" --output "嘉宾.html" name --name "周然" --role "产品负责人"
python -X utf8 -B scripts/preview_component.py --gsap "./gsap.min.js" --output "改版对照.html" compare --before "旧界面.png" --after "新界面.png" --before-label "改版前" --after-label "改版后"
python -X utf8 -B scripts/preview_component.py --gsap "./gsap.min.js" --output "导出结果.html" screen --image "点击前.png" --next "结果.png" --title "导出记录"
```

将 `./gsap.min.js` 换成已获准使用的本地 GSAP 3 运行库文件。预览器替换文字和画面，把 CDN 引用换成本机脚本。浏览器地址末尾加 `?t=1.5` 可停在 1.5 秒。姓名条在预览中有独立底色，进正式工程时可叠到采访画面。前后对比组件只标示拟音落点，实际音轨由本期剪辑安排。[组件来源及许可](../upstream/sources.md)

### 已有通用实拍从哪里取

下面三个动作可用于检索自己的素材库。选定原片后记录源时码，填入当期 B-roll 表。

| 口播中的动作 | 检索目标 | 选镜提示 |
| --- | --- | --- |
| 键入、起草 | 手指敲键盘 | 侧面手指特写，适合接在按键声前后。要教“点哪儿”，切回真实操作 |
| 记录、列清单 | 手写笔记 | 笔落纸的近景，在口播说出记录动作时进入 |
| 找书、查资料、比较颜色 | 书脊近景 | 可展示查资料的环境，也可用同一帧的彩色与黑白版本演示调色 |

剪辑时从现有库按动作找到同类，再看上一期用过哪段。新的外部素材仍先列具体作品清单给用户确认。每个项目应自行登记原片作者和许可

### 原口播先做一遍候选粗剪

用于原始采访、课程录制、自己反复重录的口播。借用 [MIT 口播剪辑 Skill](../upstream/social-media-video-editing/SKILL.upstream.md) 的声音分析和分段算法。先从源片标出必须保留的问句、笑点前停顿、静默操作和片尾结果。文案已经配好音、明确要求原声贯穿时直接跳过。

在项目的同一目录准备两份 UTF-8 JSON。下例的数字都是**源视频秒数**，示例文字和时间需替换为真实转录。多份采访分别按各自源片建单。

- `edit.json` 示例为 `{"video":"采访.mp4","style":"podcast","keep":[[0,2],[17,20]],"cut":[]}`。明确需要提议删的整次重录可写入 `cut`，一项形如 `[7.1,9.4,"从头重说，这一遍没有新增信息"]`。
- `words.json` 采用 `{"words":[{"w":"我试过。","start":2.3,"end":3.1}]}`。逐词时码越准，候选剪点越精细。只有整句起止时，按句审剪，再听两端。
- 运行 `python -X utf8 -B scripts/rough_cut_plan.py "项目/edit.json" "项目/words.json"`。它向标准输出给出保留区间、拟删区间、涉及原话、理由和预计片长。在已获准的粗剪范围内，编辑按源时码回听，自行定下普通停顿与无新增信息的重录，再用核过的 `kept_spans_s` 驱动工程。直接重跑上游渲染会由上游重新推算剪点。

默认保留中文口头语、重读和有意义的重复。音乐已经混进原声时，谨慎使用静音判断；界面停留可能是观众正在读。遇到会改变原意或与已确认版本冲突的取舍，把原话和前后关系交给作者，可并入当期方案确认。切后在同一处看“上句话尾／切点／下句话头”，听是否吞掉否定词、尾音和呼吸。客观数字、上下文和受访者口气要保住。

### 选哪一遍，字幕怎样跟着剪点走

原录有重录或专名时，在粗剪单中加两类行。听写有歧义的一行写“源时码、听写、上屏写法、核对依据”。重说的一行写“两遍源时码、各自多说了什么、拟留哪遍、接起来怎么念”。不要自动采纳最后一遍。第二遍改了数字、否定词或加了例外时，回听完整问答。两遍分别含有必要信息就保留两处；只对会改动原意的取舍请作者定。定稿配音照原声走，专名仍与当期真实资料核对。

剪点定下后，用 `python -X utf8 -B scripts/map_cues.py 保留段计划.json 源字幕.srt` 对照原编号、原词、源时码和剪后时码。工具沿用粗剪计划的 `kept_spans_s`。完整保留的句子跟新时码走；整句删除时复查绑定的画面和声音；截短、切穿的句子要试听留下的字，再拆字幕和挪动标注。此计算适用于同一源片、同顺序、原速的删剪。重排、变速、多机位或叠化要从实际工程的时间线取映射。

### 把经验交给下一次剪辑

在项目已有复盘里记“模板名、时码、填了哪份素材、用户保留或退回的原因、修后效果”。若是客户指定的颜色、IP 或音乐，留在栏目资料；若是模板本身会漏掉静默结果、裁掉按钮这类可复现问题，修共享模板并用同一段复验。更新上游时先用同一案例对比，再切换固定版本。
