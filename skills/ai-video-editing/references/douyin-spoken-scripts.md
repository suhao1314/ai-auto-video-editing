# 抖音口播怎么起稿和审稿

## 起稿前看哪些片

- **从作者发过的片子里找口吻。** 在栏目成片和发布复盘里选与本题最近的一期，听他怎样叫住观众、带人做第一步、解释生词。挑一句能代表他的原话，留意称呼、停顿和动词。对照作者亲手改定的句子，保留他明确要留的开头。只有定稿或字幕时，用它校准措辞，语气和节拍以能听到的部分为准。
- **从优质同类片里找节奏。** 先看作者点名的作品和现成的时码笔记，缺合适样本再查同受众、同用途的片段。挑一处观众产生疑问的地方，记下原片在哪句话提出问题、哪一拍给出动作或证据、何时看清结果。借这种衔接方式，用本期自己的话和材料写。例如工具教程可以从项目预览切到实际运行画面，成本分析可以在讲到数字时亮出账单中的对应一行。选哪一种，取决于这句话答应让观众看到什么。

参考只读到标题或封面时，换一条能核对的样本。工作区外使用本技能时从当期能取得的作品、字幕或作者改稿取样；样本缺失时仍可起稿，别把推测写成实看结论。

## 钩子说完，下一句怎么接

用观众认得的困惑、动作或值得看一眼的结果开场。写教程时，把第一句能照做的话接在钩子后面，旁白说出点哪里、搜什么或输入什么，画面让人知道做对了是什么样。需要账号、设备或权限才能继续，就在用到它的那一步交代。讲选择或测评时，同一位置可以给一次对比、一个可核对的结果，让观众先有判断依据。

以 GitHub 入门为例，保留作者指定的开头后，可以直接接：“打开浏览器，在地址栏输 github.com。进来以后，点上面的搜索框，把屏幕上这个项目名输进去。”网页显示搜索结果时，再指给观众看作者名。关于“为什么动手前值得搜”的建议，可以放在搜索动作上讲。小程序只用来演示怎么找到和用上一个项目，到这一步就收。

## 交稿前怎么查

顺读开头，在工作稿里标出钩子结束处和第一句有效操作；已有分镜或配音就看实际时码。逐句检查两处之间的内容：删掉这句，观众还能安全、准确地做下一步吗？能就删，或把有价值的解释移到按钮、结果出现时讲。已锁定的配音按原声配画；需要改台词时，把建议落到具体一句交作者决定。

一次 GitHub 教程的旧分镜在 10.72 秒已经说清这期教什么，到 47.44 秒才请观众输入网址。中间重复了观众已经知道的目标。这两个时码用于定位旧稿问题。新片按内容安排首个动作与阅读停留，发布后再用本账号的留存和实际追问验证效果。

按作者平时的口吻念一遍。把写得像提纲的过渡句换成眼前的动作，长项目名用屏幕承接，核对每个数字、原话、条件和承诺。为加强语气而新添的个人经历、比例或效果承诺，拿不出依据就撤掉。
